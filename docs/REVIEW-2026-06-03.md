# Benchfinity Website — Full Review

**Date:** 2026-06-03
**Scope:** Code & architecture · Security · Dependencies/CI/Docker · Performance/SEO · Accessibility · Design & content
**Method:** Six parallel dimension reviewers (63 agents, ~2.6M tokens) read the full ~2,360 LOC codebase; **every finding was then adversarially re-verified** against the actual source for reality and correct severity. Severities below are the _verified_ (post-adjudication) ratings, which are frequently lower than the first-pass ratings.
**Environment caveat:** This was a **static** review. Local Chromium cannot launch in this sandbox (Mach port restrictions, per `docs/OPEN-ISSUES.md`), so Core Web Vitals, rendered contrast, focus-ring clipping, and live response headers were **not** measured. Items needing a browser are tagged _needs-live-run_ and should be confirmed by the existing LHCI job in CI.

---

## Verdict

**The site is in strong, launch-ready shape.** It is a low-attack-surface static marketing site with a disciplined design-token system, correct Next.js 16 App Router conventions, strict TypeScript, a genuinely solid privacy-by-default analytics implementation, and an unusually complete CI/security pipeline.

After adversarial verification, **there are no critical or high-severity findings.** Two **medium** items are worth doing before/around launch; the rest are low-effort polish and maintainability cleanups.

## P1 — Medium (do these around launch)

### M1. No HTTP security headers configured `SEC-1`

**Where:** `next.config.ts` (only `output`, `pageExtensions`, `poweredByHeader:false`; no `headers()`); no `middleware.ts`, no in-repo proxy/ingress config.
**Issue:** No `Content-Security-Policy`, `X-Content-Type-Options`, `Referrer-Policy`, `X-Frame-Options`/`frame-ancestors`, `Strict-Transport-Security`, or `Permissions-Policy` are set anywhere in the repo. The Docker image runs the Next standalone server directly.
**Severity rationale:** Medium, not high — no auth/cookies/sessions to protect, so clickjacking/XSS-session impact is limited; HSTS is the most material miss. If the k8s ingress/CDN injects these, this is already covered — **verify with `curl -I` against the deployed origin** (_needs-live-run_).
**Fix:** Add an `async headers()` in `next.config.ts` applying site-wide: `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `X-Frame-Options: DENY` (or CSP `frame-ancestors 'none'`), `Strict-Transport-Security: max-age=63072000; includeSubDomains; preload`, a restrictive `Permissions-Policy`, and a CSP (allow `self`, the PostHog `api_host`; `script-src` will need a nonce or `'unsafe-inline'` for the Next bootstrap + JSON-LD).

### M2. No skip-to-content link `A11Y-1`

**Where:** `app/layout.tsx:76-81` — `<SiteHeader/>` → content → `<SiteFooter/>`, no skip link; no `<main id>` target. `SiteHeader` repeats 8 focusable elements (logo + 6 nav links + Build CTA) on every page.
**Issue:** WCAG 2.4.1 "Bypass Blocks" (Level A) failure — keyboard/AT users must tab through the full header on every navigation.
**Fix:** Add a visually-hidden-until-focused skip link as the first focusable element in `<body>` (`sr-only focus:not-sr-only`) targeting a `<main id="main-content" tabIndex={-1}>`.

## P3 — Low/info, maintainability & robustness

- **`ARCH-1`** Two MDX pipelines configured; the `@next/mdx` stack (`withMDX` wrapper, `md/mdx` pageExtensions, `@mdx-js/loader`, `@mdx-js/react`, `useMDXComponents` export) is dead weight — the blog renders via `next-mdx-remote-client`. Drop the unused deps/config. _(Keep `mdx-components.tsx`: it's a Next root-convention file; just its `useMDXComponents` export is unused.)_
- **`ARCH-3`** `readConsent`/`subscribe`/`ConsentSnapshot` and the `"benchfinity-consent-change"` event string are duplicated across `analytics-provider.tsx` and `consent-banner.tsx`. Consolidate into `lib/`. (Note: `consentChangeEvent` is _not_ exported today, so the banner can't import it — strengthens the case.)
- **`QUAL-1`** `blogFrontmatterSchema.parse()` throws on one bad post and aborts the whole `getBlogPosts()` map (build-time fail-fast; author-controlled input). Use `safeParse` + log the offending filename for diagnosability.
- **`QUAL-2`** `lib/content.ts` types `date: z.string()` with no format check; `app/sitemap.ts` does `new Date(post.date)`. Tighten to `z.iso.date()`/`z.coerce.date()` (Zod 4 is available); also makes the date sort reliable.
- **`QUAL-3`** Both dynamic routes have closed content sets but don't set `export const dynamicParams = false`. Add it for a clean static 404 path. (Already safe via `notFound()`.)
- **`QUAL-4`/`A11Y-8`** Blog page renders `<h1>` and MDX maps `#`→`<h1>`; a future post starting with `#` would emit two h1s. Map MDX `h1`→`h2`. (No current violation — existing posts have no headings.)
- **`QUAL-5`** `page_viewed` effect deps `[pathname, consent]` re-fire on consent toggle, can double-count on the same path. Gate the opt-in backfill explicitly or drop `consent` from deps.
- **`ARCH-2`** Blog post read from disk twice per request (`generateMetadata` + page). Wrap `getBlogPost` in React `cache()`. (Build-time only since statically generated — negligible impact, idiomatic fix.)
- **`DS-3`** Closing-CTA `<section>` block duplicated across 5 pages → extract a `ClosingCta` primitive (needs a few props for the variants).
- **`DS-4`** Bordered surface-card pattern (`border-bf-border bg-bf-surface border p-6`) repeated 18+ times with `p-5`/`p-6` drift → extract a `Card`/`LinkCard`.
- **`SEC-4`/`A11Y-9`** Outbound links (`TrackedLink`, footer, CTA, MDX `a`) set no `rel`. No `target="_blank"` anywhere, so tabnabbing isn't exploitable; add `rel="noopener noreferrer"` as hygiene (referrer minimization also covered by `Referrer-Policy` from M1).
- **`DEP-1`** `@types/node` is `^20` but `engines.node` is `22.x` — bump to `^22`. `eslint 10`/`typescript 6` are majors behind — treat as deliberate Dependabot upgrades. (Dev-only; not shipped.)
- **`CI-1`** All gates run in one serial `validate` job — a format failure short-circuits before lint/typecheck/audit feedback. Optional: split fast static gates from slow browser gates.
- **`DOCK-2`** Base image uses `:latest-dev` floating tag but is digest-pinned + Dependabot-managed → cosmetic; optionally use a concrete version tag for clarity.
- **`DOCK-3`** No container `HEALTHCHECK` — intentional/fine for k8s (probes live in the Deployment spec).
- **Token/style nits:** `DS-5` redundant `--bf-accent-hover` (== `--bf-accent-bright`, unused) ; `DS-6` lone inline `style={{}}` on hero background (kept as-is: a Tailwind arbitrary background-image utility makes Turbopack resolve the asset as a module and breaks the build) ; `QUAL-6` redundant `StatusPill` tone ternary ; `QUAL-7` consider `noUncheckedIndexedAccess` ; `ARCH-4` redundant `mdxComponents` re-export ; `COPY-4` hero subhead reads as an internal roadmap-labeling note.

## What's already solid (verified, no action)

- **Privacy-by-default analytics** (`SEC-5`): no PostHog client initializes and no network call fires before opt-in — lazy `import("posthog-js")`, `opt_out_capturing_by_default: true`, `capture_pageview/autocapture/session_recording` all off, consent-gated `captureAnalyticsEvent`, and `isAnalyticsConfigured()` false until tokens set.
- **Secrets hygiene** (`SEC-6`): only public `NEXT_PUBLIC_*` vars; `.env.example` is the only committed env file (gitignored otherwise); CI uses scoped `GITHUB_TOKEN` with least-privilege per-job permissions.
- **robots/sitemap** (`SEC-7`): no route leakage; `/examples` correctly `noindex` + sitemap-excluded; draft posts filtered.
- **CI pipeline** (`CI-2`, `DEP-2`): three layered security gates (`npm audit` high, `dependency-review` fail-on-high, Trivy image scan blocking fixable HIGH/CRITICAL), scan-before-push, nonroot Chainguard base, exact-pinned framework deps + committed `lockfileVersion 3` + `npm ci` everywhere.
- **App Router correctness** (code-arch summary): correct server/client boundaries (4 client components only), consistent `createPageMetadata`, `generateStaticParams`+`generateMetadata`, awaited async `params`, strict TS with no `any`/casts.
- **Accessibility baseline:** consistent landmarks, single h1 per route, labeled navs, meaningful `alt` on all images, real button/anchor controls, global `:focus-visible` ring, AA-passing contrast.
- **Design system:** single `--bf-*` token layer mirrored into Tailwind v4 `@theme`, near-zero ad-hoc hex, consistent responsive scale, reusable primitives, rigorously honest live-vs-roadmap content.
